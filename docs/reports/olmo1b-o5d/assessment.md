# O5d assessment: fusion repair survives sequential feedback

Completed 2026-09-22. The repaired O5c mixed checkpoint retains its large
WikiText improvement when evaluated with exact sequential feedback. There is
a measurable cost relative to K2, but no recurrence of the large source-model
retention deficit. All 16 fixed cases completed without weight updates or errors.

Read [results](results.md), [full evidence](report.json),
[finite/online figure](finite-online.pdf), [adaptation contrasts](adaptation-transfer.pdf)
and the frozen [protocol](protocol.md). Graphs are logged in
[W&B](https://wandb.ai/taylorbollman/pretrained-fbt-rt-nextlat/runs/jhhx390b).

## Main matched comparison

Same 512 development windows per domain, maximum 512 input tokens, batch 8,
BF16 mixed, beta 1, RT and NextLat off. Lower NLL is better:

| Endpoint / execution | Code NLL | WikiText NLL |
| --- | ---: | ---: |
| Source / K2 | 1.737004 | 4.969719 |
| Source / exact online | 1.742469 | 5.101028 |
| Repaired mixed / K2 | 1.720900 | 3.061443 |
| Repaired mixed / exact online | 1.723307 | 3.140935 |
| Shared frozen ordinary pass | 1.698216 | 3.183361 |

Mixed versus source under exact online execution improves code NLL by
0.019161 (paired original-document 95% interval: improvement 0.016791–0.021762)
and WikiText by 1.960093 (improvement 1.786748–2.103950). Thus the repair is not
confined to the ordinary-derived feedback states used by K2 training.

The remaining mixed online-minus-K2 cost is 0.002407 code NLL
([+0.001929,+0.002910]) and 0.079491 WikiText NLL
([+0.072627,+0.086351]). These correspond to about 0.24% and 8.27% higher
perplexity. The WikiText execution gap is measurable; it should not be described
as zero or dismissed as rounding noise. It is much smaller than the retained
adaptation benefit. The source already had an online-minus-K2 WikiText cost
of 0.131309; the full-context interaction interval includes zero, so do not
claim adaptation conclusively reduced that execution gap.

Against its own unchanged ordinary pass, mixed online has 0.042427 lower
WikiText NLL (difference interval [-0.056161,-0.029047]), about 4.15% lower
perplexity: 23.13 versus 24.13. It has 0.025091 worse code NLL
([+0.021790,+0.028122]), about 2.54% higher perplexity. WikiText token accuracy
is 40.597% versus 40.738% ordinary; code accuracy 63.804% versus 64.219%.
The small WikiText NLL advantage does not imply an accuracy advantage or a
uniform improvement across domains.

The full selection contains 422 original code documents / 127,850 CE targets
and 59 WikiText documents / 246,910 targets. The 1,000 paired bootstrap resamples
use original documents, combining windows before token weighting, seed 20260922.
They describe evaluation-document variability, not training-seed uncertainty.

## Pass count and the short check

Mixed full-context WikiText K3/K4/online NLL is 3.141061/3.138426/3.140935.
K4 is close to online in aggregate NLL, while K2 is better. Extra passes do
not necessarily improve predictions. The source's K3 score 4.825642 is better
than its K2, but its online score 5.101028 is worse; choosing K3 would not have
established transfer to sequential execution.

On the separate first 32 max 64 prefixes, mixed online WikiText NLL is 3.899966
versus 3.859321 K2, 5.032388 source online and 4.243235 ordinary. The repair
survives there too. This smaller selection contains just six WikiText documents.
Its source online-minus-K2 gap has the opposite sign to the full-context gap;
short and full NLL levels/effects must remain separate. No monotonic or
arbitrary-length convergence claim follows from these aggregate scores.

## What this resolves

This answers the immediate transfer concern: adapting fusion alone repaired
the measured retention failure, and that repair remains when preceding states
are generated by sequential feedback. The fixed-point-style inference path
does not recreate the large deficit on these measured contexts.

The residual finite-pass/online difference is compatible with their different
feedback-state distributions. This evaluation does not isolate every causal
contributor or measure precision error; exact online refers to the execution
semantics, not higher arithmetic precision. No nonfinite behavior or identified
numerical defect motivates reopening the precision campaign from these results.
The existing implementation and BF16 settings can remain the working baseline.

This remains teacher-forced, single-seed development evidence through 512 tokens,
not free-running generation, long-context clearance or broad general-language
benchmark reproduction. The ordinary pass received none of the new general-text
updates. Its comparison cannot establish an FBT advantage over an ordinary model
given comparable additional training. Original OLMo pretraining overlap and the
narrow WikiText training/evaluation domain remain qualifications from O5c.

## Completion and recovery

The single attempt ran 10:50:24–11:20:48 UTC, **30.4 minutes**. No restarts, training
updates or new model checkpoints were needed. Source and mixed online full-case
times are in the report; these are eager teacher-forced evaluation wall times,
not a generation-throughput comparison.

All 68 parameter/buffer hashes stayed unchanged at each endpoint after every
completed case. Their 66 native/fixed-scale hashes match exactly; only the two
fusion matrices differ. Full K2 metric containers exactly reproduce the prior
O5c starting/final evaluations, including per-document records. The earlier
source short diagnostic is also reproduced exactly. Every finite ordinary-pass
numerical/document record is invariant across endpoints and pass counts.

109 distinct scoped CPU tests passed, including existing evaluator contracts;
independent loader/runner/report review found no blocker. No core model or
frozen O5b/O5c source changed. Both figures were visually inspected. Parent
checkpoints remain at their original verified GCS identities; new evidence is
retained under the O5d lineage. See [usage](../../olmo1b-o5d-usage.md) and the
final storage receipt. The diagnostic is complete; do not relaunch it.

## Recommended next decision

Proceed to a matched ordinary additional-training control using the same
starting native backbone, code/general mixture, context boundaries and exposure
as the fusion-repair comparison. Specify adaptation capacity, learning rates
and compute differences explicitly; a frozen ordinary pass is insufficient
for the next efficacy question. Preserve this repaired checkpoint as the FBT
reference and evaluate both K2 and exact online in later comparisons.

The remaining execution gap is a possible later target for rollout-aware or
author-style prefix-mixed training if it becomes limiting. It need not block
the ordinary control or trigger another broad numerical investigation now.
No ordinary continuation, RT/NextLat interaction or new learning run has been
launched in O5d; those remain subsequent decisions.
