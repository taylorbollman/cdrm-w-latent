The ordinary-autograd FP32 CDRM reference is implemented, validated and exercised in a completed **SEQ6 versus CDRM6 pilot on MAD selective copying**. Both architectures trained for 45 epochs with paired seeds 0 and 1, followed by a fresh held-out evaluation. **This pilot shows substantial learning but no consistent CDRM advantage across seeds or checkpoint-selection policies.** It establishes a working reference; neither model comes close to solving whole sequences reliably.

The selected task has vocabulary 16, sequence length 256 and 96 copied tokens. Each final evaluation scores 122,880 answers across 1,280 fresh examples. Endpoint means the frozen common epoch 45. Best-dev means the earliest checkpoint attaining minimum development answer CE through epoch 45; it was selected before final generation. Coincident roles share an evaluation, giving six unique checkpoints and eight logical roles.

The implementation adds one causal side scan to an ordinary backbone. With six blocks and zero-based sites 1/3, ordinary blocks 0–3 produce early and late previews. The scan shares block 1's canonical attention, learned normalization and MLP weights, including differentiable fused-QKV slices. It adds exactly two nonzero, bias-free D-to-D adapters. Candidate state is `p_early + 0.1 Ad(Nd(p_late-p_early))`; each read sees earlier permanent records plus the current temporary K/V pair. The resulting permanent write becomes visible on the next token. Rho 1 stores the proposed state, and `p_late + 0.01 Ab(Nb(hat_m-p_early))` feeds suffix blocks 4–5. Memory remains connected to autograd and resets per example/forward.

Lambda zero reproduces the matched SEQ bypass; rho zero still leaves an active side branch. The active same-depth control substitutes early-preview content into the candidate adapter while keeping the late bridge anchor; it is implemented and tested, but its learning arm is deferred. CDRM is opt-in, preserving existing defaults. A wrapper compatibility fix preserves the legacy HF output tuple. See the [architecture](../../cdrm-architecture.md), [code review](code-review.md) and [usage guide](../../cdrm-naive-usage.md).

The user's six-block, SEQ-first instruction determined screening. Both seeds ran two established harder MAD settings for 25 epochs. Rapid success required token accuracy ≥99.9% and direct exact match ≥99% for three consecutive completed epochs by epoch 10; no harder screen met it. Copying reached 48.289%/66.184% dev token accuracy, above its 12.196% order-ignoring modal baseline, while retaining zero exact matches. Recall V128/T128 reached 4.915%/5.809%, below its 9.663% query-ignoring baseline, and was deferred without ruling out recurrence. Copying was [selected using development data](six-comparison-selection.json). The earlier easy SEQ12 calibration is historical; no CDRM12 research run launched.

The comparison uses D128, H16, MLP512, B128, 12,800 fixed training and 1,280 development examples, FP32/math attention, autocast/TF32/dropout off, and no accumulation. AdamW uses LR 5e-4, betas (0.9,0.98), epsilon 1e-8, zero weight decay and clip norm 1. The cosine horizon remains 200 epochs, minimum LR 1e-6, with explicit epoch-end stepping and no warmup. Training labels already align with logits; no second LM shift is applied. Copy inputs at the 96 scored positions are blanks, so answers are not fed back. Increasing copy count also reduces inserted blanks; this is not a pure memory-length change.

All four trajectories completed 25 epochs, then resumed exactly to the [runtime-selected common epoch 45](six-continuation-decision.json). The recorded 50-epoch estimate did not fit the original cutoff with its 15% margin; 45 did. The choice used runtime, not accuracy. The [full cohort audit](e45-cohort-audit.json) verifies 51 bitwise-equal initial backbone tensors per pair, two distinct nonzero CDRM adapters, identical source/config/data, all 4,500 ordered input/target/LR records, and exact inherited checkpoint/history state. CDRM starts from the corresponding fresh SEQ initialization, not a trained SEQ checkpoint.

Equal-update comparisons do not establish equal-time efficiency.

This is a two-seed, one-LR, partial-horizon pilot, not the paper's tuned one-layer reproduction; [protocol alignment](protocol-alignment.md) records the differences. It does not isolate deep-preview benefit without the deferred same-depth learning control. BF16, optimized kernels, cached decoding, packing/custom masks, activation checkpointing, accumulation and distributed execution remain outside clearance. Future result-driven changes need fresh confirmatory data.
